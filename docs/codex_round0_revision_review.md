# Codex R0 수정본 재검수

판정: **코드 및 후보 확인 정책 통과 / 평가 기준표 보완 필요**. R0 전체 완료 및 R1 착수는 평가 기준표 보완 후 확정한다. 이번에는 수정 범위를 평가 근거 문서로 좁힌다.

## 통과한 사항

- 지정 4개 회귀 테스트 재실행: **64 passed, 1 warning, 5.74초**.
- 날짜 파서의 점 구분 날짜/잘못된 입력 처리, 잘못된 offset 및 혼합 구분자 거부, 기본 ISO 날짜 및 콜론 없는 offset 호환성을 직접 재현했다.
- fixture는 23사례, 24후보이며 모든 후보에 사용자 확인이 필수다. 모호한 자정의 확정 필드는 null로 수정됐고 취소 사례가 추가됐다.
- TOPCIT 보증금 20,000원과 응시료 지원 10,000원이 구분됐고, 졸업유예 근거 URL 및 휴학 정답 조건이 수정됐다.
- 기준 JSON SHA-256은 보고서와 일치한다: `c6969ec41faa332b660186cf5407f07dc9621fcbccd2158e124e9b62c225359e`.
- 저장 계약에 날짜와 datetime 필드, 초안과 확정 저장 모델의 구분이 추가됐다. 실제 API 필드 검증은 R1에서 수행해야 한다.

## 남은 필수 수정

### 1. [P1] 상상파크 평가의 문서 ID가 다른 FAQ를 가리킴

`docs/campusmate_evaluation_baseline.md` 사례 5의 ID:

`53bdf78a6292d2880758ccd74376238bc29f21af55baf576b264a7e1c24c9153`

실제 제목은 **비교과 자격증이나 어학시험 등은 언제 기준으로 인정되나요?** 이다.
상상파크·상상파크플러스·코딩라운지 이용 FAQ의 올바른 ID는:

`002c45a581276fc882ccebe30204c976f2cac668efbd727ba16ac05672a2564f`

두 FAQ는 목록 페이지 URL이 같으므로 URL 존재 검사로는 이 오류를 찾지 못한다. ID로 문서를 찾은 뒤 제목·URL·본문을 함께 검증해야 한다. 잘못된 ID로 근거 회수율을 평가하면 정확한 검색도 실패로 채점된다.

### 2. [P2] '정확한 원문 발췌'에 재작성 문장이 남아 있음

공백·줄바꿈만 정규화한 뒤 실제 문서의 제목/본문과 대조했을 때 8개 발췌가 일치하지 않았다. 이는 모두 사실 오류라는 뜻은 아니지만 정확한 인용이라는 표시는 맞지 않는다. 사례 5의 3개 불일치는 위 ID 오류를 먼저 고쳐야 한다.

- 사례 8은 실제 원문의 `1. 대상자 : 일반편입생(외국인 유학생 제외) 중 전적대학 학점 추가인정 또는 재인정 신청 대상자`를 `1. 신청대상 : ... 재사정 희망자 ...`로 바꿔 인용했다.
- 사례 2·6에는 생략 부호로 이어 붙이거나 중간 원문을 빼고 연결한 문장을 정확한 발췌라고 적었다.
- 사례 4는 원문의 공백 경계를 바꾸었다. 공백 정규화 규칙을 적용한 실제 발췌 또는 정확한 부분 문자열 목록으로 정리하면 된다.

발췌와 요약을 별도 필드로 관리하고 발췌는 원문에 포함되는지 확인하라. 재작성 요약은 요약이라고 표시한다.

### 3. [P2] 평가 판정 문구의 불확실성·오답 조건 정리

- 사례 2는 OCR의 `184]`를 추가 검수 필요라고 표시했지만 판정 기준에는 여전히 18시를 확정 정답으로 넣었다. 이미지 미검수 상태에서 해당 시각은 NEEDS_REVIEW 또는 채점 제외로 명시해야 한다. 이번에 실 API/새 수집을 할 필요는 없다.
- 사례 7의 `제목의 '6.11' 일자는 유효 마감일로 오답 처리하지 않아야 함`은 의미가 뒤집히거나 모호하다. **6월 11일을 유효 마감일로 안내하면 FAIL, 본문 9월 17일 15:00을 근거로 안내**한다고 명시한다. 제목/본문 불일치도 알리도록 한다.
- 사례 10의 ‘식단 데이터는 ... 전혀 수집되어 있지 않음’은 범위를 좁혀야 한다. 기존 상시 안내에 식단 자료가 있으므로 **해당 기숙사·해당 주의 요청 식단 근거 미확보**로 적고 동적인 ‘이번 주’ 기준일을 고정한다.

## R1에서 확정할 설계 사항 (이번 수정 범위 아님)

- 날짜 필드와 datetime을 함께 받는 경우 Asia/Seoul 변환 날짜 일치, 시작≤종료, 일정 유형별 금지 필드 등 검증.
- 날짜-only 마감과 종일 행사 구분, 시작 날짜만 알려진 기간 등 부분 정보 초안의 저장 전환 규칙.
- 사용자 확인 시각은 서버가 기록하고 소유자는 인증 정보에서 결정한다.
- 합성 예시 source_url은 null 또는 명시적인 예시용 주소로 두고 실제 학교 출처처럼 보이지 않게 한다.

이번 검수는 보고서 주장과 로컬 데이터의 일치 및 지정 회귀 범위에 한정된다. 실 LLM, DB 영속 저장, 배포는 검증하지 않았다. 구현 코드·원시 데이터·기존 보고서는 변경하지 않았다.

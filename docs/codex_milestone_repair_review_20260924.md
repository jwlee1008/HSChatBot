## R1 — P1: 제목만 편집해도 시각이 9시간 이동하고 초가 유실됨

위치: `frontend-web/src/App.tsx:975` 부근 초기화, `:1027`–1046 payload 작성.

API로 아래 시각의 TIME_CONFIRMED_EVENT를 만들고 실제 Chromium에서 편집 모달을 열어 **제목만 변경**했다.

| 항목 | 생성 요청 | 제목 수정 후 API 응답 |
| --- | --- | --- |
| 시작 | 2026-11-20T09:00:45.123456+09:00 | 2026-11-19T15:00:00Z |
| 종료 | 2026-11-20T10:00:55.654321+09:00 | 2026-11-19T16:00:00Z |

수정 후 시작 시각은 서울 11월 20일 00:00이다. API가 정규화한 UTC 문자열에서 시각을 그대로 자르고 `+09:00`을 붙여 다시 보내므로 9시간이 이동한다. `slice(0,5)`는 초와 소수점 초도 제거한다. 제목만 수정해도 날짜 필드를 전부 PATCH하므로 사용자가 건드리지 않은 값이 덮어써진다.

수정 요구: 화면 표시는 Asia/Seoul로 변환하고, 바꾸지 않은 날짜/시간은 PATCH에서 제외하여 원본 정밀도를 보존한다. 제목/우선순위만 변경할 때 시각 불변, 서울 자정 경계, 초·소수점 초가 있는 일정, 실제 시각 변경을 각각 브라우저로 검증한다.

## R2 — P1: 추출 상수와 유효성 검사 우회가 남아 있음

위치: `backend/schedules/extraction.py:169`, `:323`–367, `:385`, `:585`, `:617`, `:720`, `:894`.

독립 입력에 `reference_time=2026-09-24T12:00:00+09:00`을 사용했다.

| 입력 | 실제 결과 |
| --- | --- |
| 오늘 18시까지 장학금 신청서를 제출하세요. | 제목이 **지도교수 면담 신청서 제출** |
| 보고서는 오늘 25시까지 제출하세요. | `2026-09-24T25:00:00+09:00`, 시각 확정 true, ambiguous false |
| 과제는 자정까지 제출하세요. | 원문에 없는 `extracted_date=2026-10-09`와 해당 날짜 해석 옵션 생성 |
| TOPCIT 구글 설문 접수 마감은 2월 30일 25:90까지이며 보증금 납부는 11월 22일 12:00까지입니다. | 첫 후보가 `2026-02-30T25:90:00+09:00`, 시각 확정 true, ambiguous false |
| 설명회 일정: 1차 2027년 11월 20일 13:30, 2차 2027년 11월 22일 23:30, 각 1시간 진행합니다. | 두 후보 모두 **2026년**; 첫 종료 14:00(14:30이어야 함); 둘째 종료 24:00(다음 날 00:30이어야 함) |

`_check_calendar_validity`는 정의돼 있지만 후반 일반 분기에만 호출된다. 앞부분 특수 분기들이 검증 없이 반환하므로 이전의 단일 반례 수정만으로 전체 입력을 보호하지 못한다. 오늘/금일/이번 주 금요일 등에는 특정 업무 제목도 그대로 남아 있다.

수정 요구: 모든 반환 경로에 공통 날짜·시간 검증을 적용하고, 원문에 없는 업무명/날짜/시각 기본값을 없앤다. 명시 연도를 보존하고 시간 연산은 datetime/timedelta로 처리한다. 기존 네 반례만이 아닌 분기별 변형 입력을 검증한다.

## R3 — P2: 출처 카드의 원문 연동은 여전히 미구현

위치: `frontend-web/src/App.tsx:264`, `:1891`.

카드의 일정 추출 버튼은 여전히 `${src.title} ${src.meta || ""}`만 보낸다. meta는 날짜와 출처명이다. URL을 함께 전달해도 추출기가 본문을 조회하지 않으므로 공지 본문에만 있는 접수일/마감일을 추출할 수 없다. 이전 수정 요청에 포함됐던 항목이다.

내부 문서 ID 기반 본문 조회를 연결하거나, 본문이 없으면 추출 대신 본문 입력을 요청해야 한다. 게시일과 실제 일정일이 다른 공지로 검증한다.

- 로그아웃: localStorage 삭제만 검사하며 이전 토큰의 `/auth/me` 401은 검사하지 않는다.
- 5종 저장: 기존 E2E는 추출 마감과 기간 이벤트만 저장한다. 이번 독립 검수에서 나머지 유형을 별도로 확인했다.

- `/api/query`는 mock 답변이다. 외부 RAG 답변 생성까지 실제 통합 검증한 것은 아니다.

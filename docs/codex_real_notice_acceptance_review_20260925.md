## N1 — P1: 잘못된 시작 시각을 검증 전에 제거하여 정상 후보처럼 반환

위치: `backend/schedules/extraction.py:594`–600, `:629`.

재현 입력:

```text
행사 안내
신청 기간: 2027.11.01 25:90 ~ 2027.11.05 18:00
```

실제 결과:

```text
start_date = 2027-11-01
start_datetime = null
end_datetime = 2027-11-05T18:00:00+09:00
is_time_confirmed = true
is_ambiguous = false
unconfirmed_fields = []
```

`has_start_time and s_hr < 24`가 false이면 원문 시각을 날짜로 바꾼다. 이후 공통 검증에는 25:90이 도달하지 않으므로 오류가 사라진다. 종료 24:00은 별도 처리하지만 시작 쪽에는 같은 보류 흐름이 없다.

수정: 시각이 없다는 상태와 잘못된 시각이라는 상태를 분리한다. 오류 시각은 명시적으로 유보하고 이유/미확정 필드를 남긴다. 시작/종료 각각의 24:00, 25:00, 23:90과 정상/시각 없음 입력을 대칭적으로 검증한다. 오류를 숨기기 위해 파싱 단계에서 정보부터 버리지 않는다.

## N2 — P2: 기간이 하나라도 있으면 단일 일정은 전부 누락

위치: `backend/schedules/extraction.py:639`의 `if not candidates:`.

실제 TOPCIT 원문에는 4단계 시험 응시 `10. 10.(토) / 9:30 ~ 12:00`, 입실완료 9:10이 있다. 현재 결과는 1~3단계 후보 3개뿐이며 시험 일정은 없다. 보증금 목표 회수 검사는 통과하므로 5/5로 드러나지 않는다.

별도 변형 입력:

```text
신청 안내
접수 기간: 2027. 11. 1.(월) 09:00 ~ 2027. 11. 5.(금) 18:00
면접 일시: 2027. 11. 8.(월) 14:00
```

실제: 접수 기간 1개만 반환. 면접 후보 없음.

수정: 이미 처리한 원문 span만 제외하고 나머지 단일 일정을 함께 추출한다. 한 날짜 아래의 시간 범위와 입실 시간도 시험의 의미에 맞게 구분한다. 종료가 없는 면접에 종료 시각을 만들지 않는다. 후보 수만 늘리지 말고 항목별 제목·시각·근거를 검증한다.

## N3 — P2: 실제 출처 제목 충돌 미검출과 일치 제목의 오검출

위치: `frontend-web/src/App.tsx:1927`, `backend/schedules/extraction.py:405`–407, `:603`–614.

1. 실제 멘토링 문서 `1a676b27...`의 별도 title에는 `9.10.목~6.11.목 15:00`, 본문 신청 기간에는 `2026. 09. 10.(목) ~ 2026. 09. 17.(목) 15:00`이 있다. 하지만 실제 추출 요청은 본문과 URL만 보내며 별도 출처 제목을 보내지 않는다. 본문 첫 줄은 인사말이다. 실제 후보는 `is_ambiguous=false`, `ambiguity_reason=null`이다. 합성 입력의 첫 줄에 제목을 넣는 검사만으로 출처 카드 통합을 증명할 수 없다.
2. 아래처럼 제목/본문이 같은 날짜여도 충돌 경고가 발생한다.

```text
프로그램 모집 안내 (2027.11.01 ~ 2027.11.05)
신청 기간: 2027.11.01 09:00 ~ 2027.11.05 18:00
```

실제: `공지 제목의 기간과 본문 신청 기간이 상이하여 확인 필요`. 정규식이 연도의 일부 `27.11`을 월/일처럼 추출하기 때문이다.

수정: 출처 제목을 별도 계약으로 전달하거나 원문과 구분되는 구조로 처리한다. 제목/본문 비교도 동일한 날짜 파서를 사용하고 정상 일치·실제 불일치를 모두 테스트한다. source_quote는 실제 본문/명시된 근거 범위를 유지한다.

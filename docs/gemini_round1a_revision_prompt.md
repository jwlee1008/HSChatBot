# Gemini R1-A 수정 요청

현재 R1-A는 Codex 검수에서 수정 필요 판정이다. docs/codex_round1a_review.md와 기존 R1-A 보고서를 읽고 아래 항목만 수정한다. 개인 일정 CRUD나 UI 기능은 추가하지 않는다.

1. 인증 요청의 422 오류 응답에서 비밀번호와 민감 입력을 제거한다. register/login의 길이 위반, 잘못된 자료형, 객체 단위 오류 및 extra field를 검사한다. 안전한 오류 위치·유형·메시지는 유지하고 기존 RAG API 계약을 보존한다.
2. 인증 테스트의 lifespan 및 요청 DB 경로를 모두 임시 디렉터리로 격리한다. 전역 환경/config 변경을 fixture 종료 시 복구하고 override도 실패 시 finally로 복구한다. 기본 계정 DB 접근이 발생하면 실패하는 검사를 포함한다. 원본 DB를 테스트 준비/정리에 사용하지 않는다.
3. malformed Bearer 토큰의 문자·길이 검증을 추가한다. 비ASCII 헤더를 포함한 잘못된 입력이 /me와 /logout에서 모두 401이며 500이나 원시 예외가 아님을 확인한다.
4. 필수 계정 DB migration 실패를 삼키지 않는다. 기존 health 정상 계약을 유지하면서 startup이 명확히 실패하도록 처리하고 합성 실패로 검증한다.
5. SQLite WAL/SHM sidecar를 Git 제외 대상에 추가한다. 사용 확장자별 check-ignore와 기존 추적 여부를 검사한다. 사용자 DB/sidecar를 삭제하지 않는다.
6. 설정 예시 및 로컬 실행·인증 API 안내를 추가한다. 기존 테스트는 TestClient/연결 재개방 증거임을 정확히 표현하거나, 임시 DB와 RAG 비활성화로 별도 프로세스 재시작을 실제 검증한다.

먼저 누락된 동작을 재현하는 회귀 검사를 작성하고 수정 후 실행한다. 인증 10개 및 관련 기존 회귀 64개와 추가 테스트의 정확한 결과를 보고한다. 실패 경로 비밀정보 검사에는 합성 입력만 사용한다. 원문 완료 보고서는 보존하고 docs/gemini_round1a_revision_report.md에 변경 파일, 실행 명령, 통과/실패 수, 데이터 격리 증거와 미검증 사항을 기록한다.

기존 수정/미추적 파일, 운영 DB, Chroma, 원시 JSON, 사용자 문서를 보존한다. 실제 LLM 호출·수집·배포·commit/push는 하지 않는다. R1-A 수정까지만 수행한다.

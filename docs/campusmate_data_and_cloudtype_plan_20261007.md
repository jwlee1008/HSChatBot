# CampusMate 현재 모델과 데이터 확장 및 무료 배포 계획

기준일 2026년 10월 7일. 로컬 코드·데이터·비밀이 아닌 환경 설정과 공식 웹 문서를 확인했다. 외부 LLM 호출, 재크롤링, Docker 빌드·배포, 계정 설정 변경은 실행하지 않았다.

## 현재 RAG의 모델

현재 로컬 `.env`는 `LLM_PROVIDER=gemini`, `GEMINI_MODEL=gemini-3.8-flash`로 설정돼 있고 Gemini 키가 존재한다. 키 값은 출력하지 않았다. 질문 임베딩은 `jhgan/ko-sroberta-multitask`를 서버에서 실행하고, ChromaDB가 관련 근거를 찾고, Gemini API가 답변을 생성한다.

gemini-3.8-flash는 [Google 공식 모델 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash)에 있는 stable 모델이다. 실제 프로젝트의 API 성공·권한·남은 호출 한도는 이번에 확인하지 않았다.

배포 장애 수정에서 Compose의 `GEMINI_MODEL` 전달을 추가하고 코드 기본값을 `gemini-3.8-flash`로 변경했다. 이 모델은 sampling 설정 없이 낮은 thinking level을 사용하도록 요청 옵션도 맞췄다. 이미지에는 `.env`가 포함되지 않으므로 키는 배포 환경변수로 제공한다. 기존 Cloudtype 서비스는 Python 템플릿이며 실제 배포 대상은 `jwlee1008/HSChatBot`의 `main`이다. 운영 설정과 확인 절차는 [Cloudtype 배포 가이드](cloudtype_chatbot_deployment.md)를 따른다.

공지 아카이브 960건과 최종 통합 공지 986건은 별도 수치다. 아카이브는 일반 공지 45페이지에서 수집 개수 제한에 도달했으며 목표 날짜에 도달하지 않았다. 학교 전체·최근 3년 전체 공지를 확보한 상태는 아니다. 현 수집 범위 밖의 학과·단과대·시설 자료는 추가 URL과 전용 수집기가 필요하다.

## 추가 자료를 반영하는 작업

1. **우선순위 질문과 URL 확정:** 수강·장학·졸업·휴복학·시설부터 실제 학생 질문에 필요한 게시판·안내·정정 공지를 정한다.
2. **최신 공지와 안내 수집:** `crawler/hansung_pw.py`, `crawler/official_site.py`, `crawler/faq.py`를 이용해 9/15 이후 자료와 변경된 안내를 갱신한다. 과거 자료는 `crawler/notice_archive.py`의 게시판·기간·개수 제한과 보고서를 관리하며 추가 수집한다.
3. **본문과 첨부 보강:** `scripts/enrich_notices.py`, `scripts/enrich_official_pages.py`로 텍스트를 확보하고 핵심 날짜·대상·제외 조건의 OCR를 원문과 비교한다. 실패·암호화·동적 자료는 숨기지 않고 상태로 기록한다.
4. **새 공지를 통합 입력에 연결:** `scripts/build_unified_dataset.py`의 현재 5개 입력에는 정기 수집 파일 `crawled_notices_enriched.json`이 없다. 해당 입력을 추가하고 최신 정정본·본문 품질·실패 시 이전 성공본 보존 규칙을 적용한다.
5. **통합본과 새 색인 검증:** 새 경로에 통합 JSON·manifest·Chroma DB를 만들고 수·ID·해시·대표 질문 근거를 검사한다. `scripts/ingest_unified_db.py`를 사용하며 기존 실행 DB를 검증 전 덮어쓰지 않는다.
6. **서비스 반영:** 검증한 JSON과 DB를 배포 버전에 포함하고 서비스를 새 버전으로 갱신한다. 서버가 실제 사용하는 자료 버전을 확인하고 이전 성공 버전으로 복구할 수 있게 한다.
7. **정기 연결:** 기존 `.github/workflows/crawl.yml`과 `official-site.yml`을 수집→보강→통합→색인→검증→배포까지 연결한다.

현재 공지 워크플로는 매일 06:00 KST에 수집·보강하지만 커밋은 `crawled_notices*.json`에 한정된다. 공식 안내 워크플로는 06:20에 HTML·FAQ를 갱신한다. CI의 임시 DB 생성이나 JSON 변경만으로 서비스의 통합 검색 DB가 갱신되지는 않는다.

이 작업은 새 기능을 처음부터 만드는 것보다 **기존 수집기와 통합·적재 스크립트 사이의 연결을 완성하는 일**이 우선이다. 자료 범위를 추가할 때는 출처 URL, 수집 기간, 적용 연도·학기, 확인 시각, 실패 상태를 함께 기록한다.

## Cloudtype 무료 환경 판단

공식 [요금표](https://cloudtype.io/pricing)는 무료 메모리 1GB, 임시 디스크 1GB, 이미지 제한 1GB, 매일 1회 중지와 카드 등록 필요를 안내한다. 임시 디스크는 초기화될 수 있다. 시연·학습 환경으로 검토할 수 있지만 현재 구성 그대로의 실행 가능성은 실제 자원 측정 전 확정할 수 없다.

공식 [Docker 문제 해결](https://docs.cloudtype.dev/ko/troubleshooting/dockerfile)의 과거 기본 2GB 이미지 안내와 요금표가 달라, 준비는 더 엄격한 1GB를 기준으로 한다. Linux AMD64 이미지와 실행 환경을 확인해야 한다. 기존 서비스의 Python 배포와 새 Dockerfile 적용은 별도로 확인한다.

개인 일정 저장을 제외한 챗봇에서는 PostgreSQL 이식을 필수로 할 필요가 없다. 공개 JSON과 Chroma seed를 배포 버전에 포함해 재시작 시 복원할 수 있다. 다만 로컬 한국어 임베딩은 여전히 모델 가중치·PyTorch·메모리를 필요로 한다. 현재 구성의 AMD64 이미지 크기와 모델 초기화·질의 중 최대 메모리 측정은 없다. 과거 ARM64 회귀 통과나 로컬 파일 크기를 무료 환경 실행 증거로 사용하지 않는다.

권장 구조는 다음과 같다.

- 로컬 또는 GitHub Actions: 수집, OCR, 첨부 보강, 통합, 색인, 검증.
- Cloudtype: React 정적 화면, FastAPI, Chroma 검색, 질문 임베딩, Gemini 답변 생성.
- 자료 갱신: 검증한 새 JSON·색인을 버전으로 배포. 런타임 임시 파일만을 유일한 원본으로 두지 않는다.

먼저 현재 임베딩을 유지해 이미지 크기와 실제 최대 메모리를 측정한다. 한도를 초과하면 실행용 의존성을 줄이고, 경량 임베딩이나 외부 임베딩을 검토한다. 임베딩 모델을 바꾸면 기존 청크 전체를 새 모델로 재색인해야 한다.

무료 호스팅은 지속 운영이나 무제한 Gemini 호출을 보장하지 않는다. 실제 제공자 계정의 한도는 [Gemini 호출 한도](https://ai.google.dev/gemini-api/docs/rate-limits)와 AI Studio에서 확인한다. 호스팅과 LLM의 비용·한도는 각각 관리한다.

## 우선 다음 작업

1. 최신 수집 파일의 통합 입력 연결과 데이터 갱신.
2. Gemini 배포 모델 환경변수 정합성 확인.
3. Linux AMD64 최신 이미지 크기와 임베딩 실행 RAM 측정.
4. 한도 안에서 첫 질문·반복 질문·재시작을 검증한 뒤 무료 환경 배포 여부 결정.

이번에 애플리케이션 코드·배포 설정을 수정하거나 자료를 재수집하지 않았다. 이 문서는 확인 결과와 다음 작업의 기준이며, 실행 완료 기록이 아니다.

### 2.2 [P2] '정확한 원문 발췌' 전수 정비 및 공백 정규화 규칙 명문화 (사례 1~9)
- **공백 정규화 규칙 명시 (Normalization Rule):**
  - 모든 발췌문(`quotes`)은 문서 제목 또는 본문에 존재하는 **연속된 부분 문자열(Exact Substring)**이거나, 줄바꿈·탭·공백(`\s+`) 및 비분리 공백(`\xa0`)을 단일 공백(`' '`)으로 치환한 **공백 정규화 부분 문자열(Whitespace Normalized Substring)**이어야 함.
  - 임의의 생략 부호(`...`)나 중간 문장을 건너뛰고 결합한 가공 문장은 발췌에서 배제하고, 복합 문맥은 개별 발췌 목록으로 분리.
  - 가공·재작성된 문장은 '요약(Summary)' 필드로 완전히 분리하여 표기.
- **주요 수정 사례:**
  - **사례 8 (편입생 전적대학 학점인정):** 기존의 임의 재작성 문장(`1. 신청대상 : ... 재사정 희망자 ...`)을 원문 그대로 복사한 `"1. 대상자 : 일반편입생(외국인 유학생 제외) 중 전적대학 학점 추가인정 또는 재인정 신청 대상자"`로 정정.
  - **사례 2 (국가장학금 2차 신청):** `...`로 이어붙였던 발췌를 원문 3개 라인(`"'26.8.12.(수) 09시~9.9.(수) 18시"`, `"서류제출 및 가구원 동의"`, `"26.8.12.(수) 09시~9.16.(수) 184]"`)으로 분리.
  - **사례 6 (TOPCIT 정기평가):** 중간 표 구조를 건너뛰고 합쳤던 발췌를 5개 개별 원문 발췌로 분리.
  - **사례 4 (휴학):** 원문의 개행 경계(`'신입생\n은 병역 또는 질병에 의한 경우 이외에는\n입학 년도의 휴학을 할 수 없다.'`)를 반영하여 공백 정규화 적용 발췌로 명시하고 요약을 분리.

## 3. 재현 가능한 검증 도구 및 실행 결과

손으로 다시 추정하지 않고 로컬 JSON 파일과 10사례 명세를 프로그램적으로 전수 대조하는 전용 스크립트 `scripts/verify_rag_eval_evidence.py`를 작성하여 실행하였습니다.

### 3.1 검증 스크립트 (`scripts/verify_rag_eval_evidence.py`) 설계
- **범위 한정:** 대표 10사례에만 범위를 한정하고 공통 dataset hash, case id, doc_id, url, title, quote list, review status를 구조화하여 관리.
- **무결성 검사:**
  1. `data/unified_campus_knowledge.json`의 SHA-256 해시 대조 (`c6969ec41faa332b660186cf5407f07dc9621fcbccd2158e124e9b62c225359e`).
  2. Document ID 매핑 및 존재 여부 확인.
  3. URL 및 제목(정규화 후 포함 여부) 일치 검사.
  4. 모든 발췌문에 대해 원문 raw 텍스트 내 Exact Substring 또는 공백 정규화 Substring 존재 여부 전수 검증.
  5. 근거 부재 사례(case-10)의 `doc_id: null`, `url: null`, `quotes: []` 정책 준수 검증.

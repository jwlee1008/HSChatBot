# Gemini R1-B 수정 요청

R1-B는 Codex 검수에서 수정 필요다. docs/codex_round1b_review.md와 기존 구현 프롬프트를 읽고 아래 문제만 수정한다. 개인 일정 모델/API의 기존 계약, R1-A 인증, 기존 RAG API를 보존한다. R2 추출·UI·알림은 추가하지 않는다.

1. **동시 PATCH 데이터 유실 차단:** 현재 읽기/병합/검증 이후 BEGIN IMMEDIATE를 시작하여 동시 요청이 다른 필드 변경을 되돌린다. 읽기부터 쓰기까지 보호하는 트랜잭션 또는 안전한 충돌 검사를 적용한다. 모든 예외/404/422 경로에서 rollback/정리를 보장한다. 동시 title/description 수정이 둘 다 성공하면 둘 다 남아야 한다. 수정/삭제 경합도 안전하게 처리하고 rowcount 및 응답 조회 경계를 검토한다. 테스트는 요청 순서를 결정적으로 제어하되, 잠금 안에서 두 요청이 모두 도착해야 풀리는 barrier로 수정된 구현을 교착시키지 않는다.
2. **일시 정밀도 정책 확정:** 소수점 초를 보존하거나 미지원 입력을 명시적 422로 거부한다. 현재처럼 절단하여 start=end인 일정이 201 저장되면 안 된다. 저장→GET→제목만 PATCH 후 시간 불변식을 검증한다. UTC/서울 변환 범위 초과도 500 대신 안전하게 거부한다. 가이드에 정책을 기록한다.
3. **source_url 검증:** 접두사 검사 대신 실제 URL 검증으로 http/https, 유효 host, 최대 길이를 확인한다. `https://`, `https://not a host`, `http://?query`를 CREATE/PATCH에서 거부한다. 정상 URL·nullable·비지원 scheme도 검사한다. URL 네트워크 요청은 하지 않는다.
4. **migration 증거 보강:** 실제 비밀번호 해시를 가진 v1 사용자와 유효 세션을 구성하여 v2 후 기존 비밀번호 재로그인과 기존 세션 유지, 일정 생성, 반복 migration 보존을 확인한다. v2 migration 중간 합성 실패로 테이블/인덱스/버전 기록 롤백과 v1 데이터 보존을 검증한다. 원본 DB는 사용하지 않는다.

재현 회귀를 먼저 작성하고 수정 후 신규 테스트와 기존 승인된 인증/RAG 관련 회귀를 실행한다. 테스트 개수를 목표로 삼지 않는다. lifespan과 요청 DB를 모두 임시 경로에 주입하고 RAG prewarm을 끈다. 기본 계정 DB 및 Chroma 접근을 차단하며 검증한다.

기존 수정·미추적 파일, 원본 보고서·데이터·사용자 문서를 보존한다. 실제 LLM/크롤링/배포/commit/push 및 의존성 전체 업그레이드는 하지 않는다.

산출물: 수정 구현·회귀 테스트, 필요 시 API 가이드 정정, docs/gemini_round1b_revision_report.md. 보고서에 각 문제의 재현/수정, 실제 실행 명령과 결과, DB 격리 및 migration 보존 증거, 미검증 범위를 기록한다. R1-B 수정까지만 완료하고 Codex 재검수를 기다린다.

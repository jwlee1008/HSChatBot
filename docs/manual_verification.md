# CampusRAG 수동 검증 가이드 및 잔여 이슈 인계서

본 문서는 CampusRAG 시스템을 직접 실행하여 수동 검증을 진행할 때 필요한 환경, 절차, 테스트 시나리오, 그리고 현재 시스템의 알려진 결함 및 미완료 항목을 정리한 인계 문서입니다.

---

## 1. 사전 환경 및 설치 요건

- **운영체제**: macOS (Apple Silicon MPS 지원 권장) 또는 Linux
- **Python 버전**: Python 3.12 이상
- **가상환경 활성화**:
  ```bash
  source .venv/bin/activate
  ```
- **의존성 패키지**:
  ```bash
  pip install -r requirements.txt
  playwright install chromium
  ```
- **실행 모델**:
  - 한국어 임베딩: `jhgan/ko-sroberta-multitask` (SentenceTransformers)
  - 로컬 LLM: `Qwen/Qwen2.5-1.5B-Instruct` (HuggingFace Transformers, Apple Silicon MPS 또는 CPU)

---

## 2. 검증용 격리 DB 정보

운영 DB(`data/chroma_db`)의 무결성을 보호하기 위해, 수집 공지 99건을 해시 동기화하여 구축한 **격리 검증 DB**를 사용합니다.

- **DB 디렉터리 경로**: `data/verify_demo_chroma_db`
- **Chroma 컬렉션명**: `campus_notices`
- **데이터 현황**:
  - 적재 공지 수: 99건 (`data/crawled_notices.json`과 100% ID 및 SHA256 해시 일치)
  - 적재 청크 수: 217건
  - 본문 확보: 66건 (text), 본문 미확보: 33건 (title_only)
- **보안/보존 원칙**:
  - `.gitignore`에 `data/*_chroma_db/` 패턴을 추가하여 git 추적 및 커밋 대상에서 제외되어 있습니다.
  - 운영 DB(`data/chroma_db`)는 본 검증 중 일절 수정되지 않고 보존됩니다.

## 3. 서비스 실행 및 종료 명령

검증용 DB를 바인딩하여 백엔드(FastAPI)와 프론트엔드(Streamlit)를 실행하는 정확한 절차입니다.

### 1) 백엔드 API 서버 실행 (Terminal 1)
```bash
CHROMA_PERSIST_DIR=data/verify_demo_chroma_db CHROMA_COLLECTION_NAME=campus_notices .venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000
```
- 정상 기동 확인:
  ```bash
  curl -s http://127.0.0.1:8000/health
  # 기대 출력: {"status":"ok","version":"1.0.0","llm_provider":"local","doc_count":217}
  ```

### 2) 프론트엔드 웹 UI 실행 (Terminal 2)
```bash
STREAMLIT_SERVER_HEADLESS=true .venv/bin/streamlit run frontend/app.py --server.address 127.0.0.1 --server.port 8501
```

### 3) 접속 주소
- **사용자 웹 인터페이스**: [http://127.0.0.1:8501](http://127.0.0.1:8501)
- **백엔드 API 및 Swagger 문서**: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

### 4) 정상 종료 방법
- 각 실행 터미널에서 `Ctrl + C`를 눌러 정상 종료합니다.
- 백그라운드 프로세스가 남아있는 경우 아래 명령으로 정리합니다:
  ```bash
  kill $(lsof -t -i:8000 -i:8501)
  ```

## 5. 남은 문제 및 미해결 결함 기록 (해결 처리 금지)

아래 항목들은 **미해결 결함 및 한계 사항**으로 분류되어 있으며, 해결된 것으로 간주하지 않습니다.

### 1) 단축 검색어("TOPCIT 평가") 유사도 미달 결함
- **현상**: `"TOPCIT 평가"`(2단어)로 검색하면 공지가 존재함에도 원시 코사인 유사도가 `0.225`로 산출되어 관련도 임계값(`0.25`) 미달로 검색 결과가 0건 반환됨. `"TOPCIT 정기평가"`로 검색해야만 점수 `0.260`으로 통과.
- **사용자 영향**: 학생이 약칭이나 짧은 명사구로 검색할 경우 존재하는 공지를 찾지 못하는 거짓 부정(False Negative) 발생.
- **재현 절차**:
  1. 검색창에 `"TOPCIT 평가"` 입력 → 결과: "관련 공지를 찾지 못했습니다" (실패)
  2. 검색창에 `"TOPCIT 정기평가"` 입력 → 결과: 2건 공지 정상 검색 (성공)
- **다음 조치**:
  - E2E 테스트에서 입력을 수정한 것은 테스트 통과를 위한 임시 조치이며 제품 결함 해결이 아님.
  - 임베딩 단어 매칭 한계를 보완하기 위해 키워드 BM25 + Dense 하이브리드 검색 도입 또는 학내 축약어(TOPCIT, 편입 등) 동의어 사전 확장 필요.

### 2) 알려진 FAIL 3건 (원문 대조 실측 결과)
1. **`dev-md-05` (국가전문자격시험 장학금 대상 부인)**
   - **재현 질문**: `"국가전문자격시험 합격생 장학금 대상에 공인회계사랑 세무사도 포함돼?"`
   - **현상**: 원문에 CPA(공인회계사)와 세무사가 명시되어 있으나, 소형 LLM이 반대로 "포함되지 않는다"고 오답 생성.
   - **사용자 영향**: 자격 대상 학생이 장학금 지원을 포기할 위험.
   - **다음 조치**: 부정 질문 대응 프롬프트 강화 및 자격시험 목록 매칭 가드레일 추가.
2. **`test-md-07` (공지 제목 오타 인용)**
   - **재현 질문**: `"2026학년도 2학기 전공연계 협업형 진로·취업멘토링 참가자 신청 기간이 언제야?"`
   - **현상**: 본문 상세 마감일(9월 17일 15:00) 대신 학교 포털 원본 공지 제목의 오타 표기(`6월 11일`)를 답변에 그대로 인용.
   - **사용자 영향**: 과거 날짜로 안내되어 학생이 신청 기간이 지난 것으로 오인.
   - **다음 조치**: 본문과 제목의 일정이 상충할 경우 본문 상세 일정을 우선하도록 프롬프트/파서 개선.
3. **`test-md-09` (무관 공지 언급)**
   - **재현 질문**: `"한성대 기숙사 우촌학사 야간 통금 시간이 몇 시야?"`
   - **현상**: 통금 시간 정보 부재는 밝혔으나, 함께 검색된 무관 채용 공지 제목을 부가 설명에 불필요하게 언급.
   - **사용자 영향**: 답변의 신뢰도 저하 및 혼란 유발.
   - **다음 조치**: 근거 없는 질의에 대한 완전 유보 템플릿 강제.

## 수정 확인

- `_validate_and_normalize_candidates`의 `explicit_doc_year`, `expected_year`, 연도 문자열 replace 로직이 제거됐다.
- 시작/종료 날짜의 명시 연도가 각각 보존되고, 해당 기간 분기에서 연도 누락 시 월 경계를 근거로 추론한다.
- 오늘/내일은 reference_time을 사용하며 문서의 무관한 사업 연도에 영향받지 않는다.
- 공통 달력·시각·기간 순서 검증은 유지됐다.
- 기존 8대 반례는 회귀 테스트에 포함되어 통과했다.

추가 독립 검사는 다음 17개 입력으로 구성했다.

1. 시작 연도 2024/2025/2026/2027 각각의 12월 30일 → 다음 해 1월 5일 기간, 시각 포함/날짜 전용 각 1개: 8개.
2. 무관한 사업 연도 2024/2025/2027/2028 각각과 오늘/내일 표현 조합: 8개. reference_time은 2026-09-25T12:00:00+09:00으로 고정했다.
3. 2027년 1차 13:30 및 2차 23:30, 각 1시간 진행: 1개. 종료 14:30 및 다음 날 00:30과 명시 연도 보존을 확인했다.

브라우저 E2E에서는 선택 후보의 정확한 날짜/시각, 모달 취소 미저장, 기간 중간 날짜 필터, 제목/시작/종료 독립 편집과 미수정 필드 보존, 서울 자정, 페이지네이션, 로그아웃 후 토큰 401 검증을 재실행했다.

## 남는 범위 제한

- 150개는 지정한 9개 파일의 선별 회귀이며 저장소 전체 테스트가 아니다.
- E2E의 `/api/query` 응답은 mock이다. 실제 LLM/RAG 질의부터 저장까지의 운영 통합 검증과 구분한다.
- RAG 10사례는 로컬 근거 일치 검사이며 검색·생성 정확도나 OCR 원본 정확도 전수 보증이 아니다.
- 출처 본문은 검색 청크 최대 2,000자이며 전체 공지/첨부파일을 모두 전달하지 않는다.
- 운영 알림과 배포 범위 결정은 별도 과제로 남는다.

애플리케이션 코드를 수정하거나 외부 LLM/크롤링/배포/커밋/푸시를 수행하지 않았다. 이번 라운드용 추가 Gemini 수정 요청문은 필요하지 않다. 다음 단계는 정해진 실제 공지 사례로 사용자 수용 검증을 진행하고 운영 범위를 결정하는 것이다.

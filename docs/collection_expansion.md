# 공식 정보 수집 확장 — 2026-09-14 1차 구현

## 현재 범위와 실행 방법

기존 RAG 작업은 `8c6015f`에 보존했다. 이번 변경은 운영 DB를 변경하지 않고
별도 JSON에 학교 공식 정보를 수집한다. 앱 배포·운영 DB 반영은 아직 수행하지 않는다.

```bash
# 교육정보·대학생활·한성소식 메뉴 및 하위 탭 탐색, 갱신 시기가 된 URL 수집
.venv/bin/python -m crawler.official_site --max-pages 200
# 선택한 게시판의 과거 공지 추가 수집. 다음 실행은 이미 성공한 공지를 건너뛴다.
.venv/bin/python -m crawler.notice_archive --boards 2127 --since 2023-09-14 --max-pages 300 --max-notices 300
# 최근 범위의 수정도 확인하려면 --refresh 사용. 첨부 추출은 --enrich-attachments 명시.
# 기존 제목 전용 공지 재조회 및 OCR/첨부 추출. 입력 JSON은 보존한다.
.venv/bin/python scripts/refresh_missing_notices.py
```

`--max-pages`, `--max-notices`는 한 번의 실행 상한이다. 상한 도달은 전체 수집 완료가 아니다.
`notice_archive.json.report.json`의 `reached_since`, `list_complete`, `limit_reached`를 확인해야 한다.
중단 후 다시 실행할 수 있으며 성공한 공지는 매 건 저장한다. 갱신에 실패하면 이전 본문을 유지한다.

## 자료와 수집 주기

- `data/official_pages.json`: 공식 상시 안내의 본문·표·출처·메뉴 경로·담당부서·학교 수정일·확인 시각.
- `data/official_site_inventory.json`: 수집 대상, 게시판 연결, 외부 링크, 누락·실패 이유.
- `data/notice_archive.json`: 별도 공지 아카이브. 일반 텍스트 수집과 이미지/첨부 추출 여부를 구분한다.
- `data/missing_notices_refreshed.json`: 기존 99건 중 제목 전용 공지를 다시 처리한 별도 결과.
- `*.report.json`: 실행 상한 및 오류, 미처리 상태를 포함한 실행 보고.

공지의 기존 일일 workflow는 유지한다. 새 `official-site.yml`은 매일 실행하되 각 URL의
성공한 `last_checked_at`을 기준으로 기본 14일, 학사일정은 1일 경과 시 수집한다.
`crawler/source_policies.json`의 `interval_overrides`에 URL별 1/14/30일을 지정할 수 있다.
강제 갱신은 `--force`다. 아직 기본 브랜치에 병합하지 않았으므로 새 정기 workflow는 활성화되지 않았다.
HTML 요청은 조건부 GET이 아니라 제한된 주기의 GET이며, 본문 해시로 내용 변경을 판정한다.
현재 자동화는 JSON까지 갱신한다. 서비스 DB 반영이나 무중단 배포를 수행하지 않는다.

## 기존 제목 전용 공지 재처리

기존 99건 중 제목만 있던 33건을 별도 JSON으로 재처리했다. 22건은 OCR, 11건은 혼합 추출로
텍스트를 확보했다. 이는 추출 성공 상태 집계이지 날짜/조건의 정확도 검증 결과는 아니다.
실제 재조회 시 본문 텍스트 없이 이미지·첨부가 존재한 경우가 확인돼, 과거의
“33건 모두 상세 HTML 미수집 때문”이라는 원인 단정은 철회한다.
`data/missing_notices_refreshed.json.report.json`에 URL별 HTML 글자 수, 이미지/첨부 수와 결과를 남겼다.
손상 HWP에서 나온 단독 UTF-16 surrogate 때문에 JSON 저장이 중단되는 문제는
저장 시 대체문자로 정규화해 처리했다. 원문 다운로드 캐시는 그대로 보존한다.

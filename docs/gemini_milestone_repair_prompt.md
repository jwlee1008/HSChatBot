# Gemini 수정 요청 — CampusMate 완료 판정 보류 사항

`docs/codex_full_milestone_review_20260924.md`를 먼저 읽고 실제 재현 결과에 근거해 수정해줘. 이번 작업의 목표는 R2/R3 사용자 흐름 복구이며 전체 마일스톤 완료를 선포하지 마.

## 수정 범위와 우선순위

1. F1: 모달이 보내는 요청을 기존 ScheduleCreateRequest 계약에 맞춰줘. 응답 계산 필드를 보내지 말고 서버 extra=forbid를 유지해. 5가지 일정 종류의 실제 브라우저 저장을 확인해.
2. F3: 공통 비밀번호 자동 게스트 생성 경로 두 곳을 제거하고 기존 로그인/회원가입 UI를 사용해. 로그아웃 API를 연결하여 이전 토큰이 401이 되는지 확인해. 인증 실패도 화면에 처리해.
3. F4: 실행 시각을 서울 기준으로 처리하고 테스트만 clock/reference_time을 고정해. 없는 날짜/시각을 오늘/09:00/18:00으로 자동 채우지 말고 사용자가 입력하기 전 저장을 막아.
4. F2: 예제별 상수 날짜·제목·근거를 반환하는 분기를 일반 원문 파싱으로 교체해. 실제 연도/날짜/시간을 검증하고 불명확하면 미확정/유보해. source_quote는 입력의 실제 구간이어야 해. 보고서의 네 가지 반례와 제목/날짜/연도/문장순서 변형 사례를 검증해.
5. F5/F6: 모든 후보를 표시하고 사용자가 고른 후보만 저장해. 취소 공지를 일반 신규 일정으로 저장하지 말고 기간 의미를 유지해. 출처 카드에서 원문 없이 추출하지 말고 기존 내부 문서 조회를 통해 확보한 본문을 사용하거나 본문 입력을 요청해. 목록 페이지네이션, 기간 날짜 표시, 기존 일정 내용 편집을 연결해.
6. F7: 이번 수정에서 운영 알림을 성급히 추가하지 말고 현재 배너/수동 알림의 범위와 미구현 항목을 정확히 기록해. 별도 알림 확장/배포는 후속 과제로 남겨.

## 제약

- 기존 인증, BOLA, 원자적 PATCH, 시간 정밀도, URL 검증과 confirmed 계약을 약화하지 마.
- 저장소 data 파일 및 실제 사용자 DB를 수정하지 마. 테스트는 임시 DB, RAG prewarm off로 실행하고 데이터 해시를 전후 비교해.
- 외부 LLM/크롤링/배포/커밋/푸시는 하지 마.
- 픽스처 기대값을 구현의 잘못된 결과에 맞추거나 예제 입력에만 통과하는 분기를 추가하지 마.

## 검증과 산출물

- 기존 145개 회귀와 빌드를 유지해.
- API 통합 테스트와 실제 브라우저 E2E를 구분해. 브라우저에서 추출 → 후보 선택 → 수정 → 저장 → 재조회 → 내용 편집 → 완료 → 삭제를 실행해. 취소/미선택 시 미저장, 복수 후보 두 번째 선택, 51건 이상, 서울 자정 경계, 로그아웃 후 토큰 무효화를 확인해.
- 브라우저 테스트는 임시 DB의 로컬 서버와 실제 최신 빌드를 사용하고 재현 가능한 테스트 파일/실행 명령을 남겨.
- `docs/gemini_milestone_repair_report.md`에 F1~F7별 변경 파일, 검증 명령과 실제 결과, 미해결 항목을 기록해. 완료/부분 구현/미구현을 분리해 보고해.

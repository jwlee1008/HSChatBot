# Codex 재검토: Gemini 통합 변경

현재 판단: 통합 데이터 생성과 오류 처리의 기반은 추가됐지만, 병합/운영 반영 전 수정이 필요하다.
검토 중 Gemini API 호출과 운영 DB 변경은 하지 않았다.

## 수정 필요 사항

1. **데이터 갱신 우선순위 (P1)** — `scripts/build_unified_dataset.py:204`
   `missing_notices_refreshed`와 서식 보강본은 이후 아카이브가 무조건 덮어쓰지 못한다.
   수집 시각을 비교하지 않으며, 다른 경우에도 긴 본문을 우선한다.
   최신 공지의 마감 정정/본문 축소가 들어와도 과거 정보를 영구 보존할 수 있다.
   실패 보존과 정상 변경 반영을 구분하고, 문서별 채택/기각 이유와 버전 충돌을 기록해야 한다.
   227행은 새 문서가 채택되지 않은 길이 비교 분기에서도 `_source_name`을 바꾸므로 출처 추적도 수정해야 한다.

2. **격리 DB 경로 방어 (P1)** — `scripts/ingest_unified_db.py:35`
   기존 경로·운영 경로·심볼릭 링크를 거부하지 않고 전달된 경로에 바로 적재한다.
   기존 DB에 재실행하면 삭제된 문서/줄어든 청크를 제거하지 않아 잔존 근거도 생긴다.
   이번 스크립트는 새 경로만 허용하고 기존 경로를 변경 전 거부하는 방식으로 제한하라.
   운영 DB/기존 검증 DB/링크 대상/삽입 실패 시 보존을 임시 경로에서 테스트하라.

3. **무관 질문 사전 필터 우회 (P1)** — `core/rag.py:304`
   일반 단어·연도 하나만 제목에 있어도 원시 관련성에 0.08을 더해 통과시킨다.
   Codex mock 재현: 원시 점수 0.18인 '2026년 장학금 안내'가
   '2026년 아이폰 스펙 알려줘' 질문에 반환된다(임계값 0.25).
   실제 HTTP 기록에서도 파이썬 코드 질문이 유보되지 않고 Gemini까지 호출돼 429를 받았다.
   TOPCIT를 살리면서 일반 단어·연도만 겹치는 무관 문서는 차단하는 회귀 테스트가 필요하다.

4. **서비스 응답에서 오류 상태 유실 (P1)** — `backend/main.py:145`
   RAG는 status/api_called/provider/model을 반환하지만 QueryResponse는 answer/sources만 반환한다.
   HTTP 기록에는 429 안내가 HTTP 200 일반 답변으로만 보이며 정상 생성과 구조적으로 구분되지 않는다.
   HTTP 200 자체가 반드시 잘못은 아니지만, 계약에 명확한 상태가 있어야 한다.
   응답 스키마와 프론트엔드까지 오류 상태를 전달하고 원시 예외/비밀정보를 사용자 응답에 노출하지 마라.
   정상 응답, 무관 유보, title_only, 429, 503 소진, 인증 오류를 mock HTTP/UI 경로에서 검증하라.

5. **검증 결과와 완료 주장의 불일치 (P2)**
   `data/gemini_integration_results.json`의 9개 프로브는 전부 api_error다.
   이 파일만으로 보고서의 6대 사례 'Gemini 생성 PASS'를 뒷받침할 수 없다.
   다른 성공 실행이 있다면 정확한 원시 파일/질문 ID/시각을 연결하고, 없으면 검색 확인과 답변 미검증으로 정정하라.
   신규 10문항 평가에서는 실제 PASS 1개, API_ERROR 9개다. 단 하나의 성공 호출은 약 3.64초다.
   오류 9건이 섞인 p95 2.25초를 정상 생성 지연 개선으로 해석할 수 없다.
   성공 생성/조기 유보/오류 지연을 분리하고, 429 반복 시 체크포인트 후 중단하라.
   미시도 항목은 NOT_RUN으로 남기며 오류/정답과 구분하라.
   일일 할당량 소진은 요청 간격을 15~20초 늘려 해결할 수 없다. 분당 제한과 구분하라.

6. **검색 테스트가 검색을 검증하지 않음 (P2)** — `tests/test_retrieval_grounding.py`
   `test_short_query_lexical_preservation`은 CampusRAG를 생성하고 vectorstore 존재만 검사한다.
   TOPCIT 질문을 실행하거나 결과를 검증하지 않으므로 결함을 잡을 수 없다.
   또한 생성자 호출은 기본 설정 DB를 열 수 있으므로 단위 테스트에서 외부 DB/모델 의존을 제거하라.
   통합 데이터 선택/FAQ ID 보존/청크 누락 방지/상시 안내 시간 정책에도 실제 동작 회귀 테스트를 추가하라.

## 추가 주의

- 202건 title_only라는 사실만으로 '모두 HWP 문제'라고 원인을 확정하지 마라.
- text/mixed 상태 건수를 '본문/OCR 완벽 확보'로 표현하지 마라. 부분 추출과 OCR 오류가 남을 수 있다.
- 기존 20/25문항 전체 회귀 및 UI 검증은 이번 16개 단위 테스트 통과로 대체되지 않는다.
- 이번에는 새로운 API 호출 없이 위 수정과 mock/fixture 검증을 우선한다.
- 커밋/push/운영 DB 교체/유료 전환은 수행하지 않는다.

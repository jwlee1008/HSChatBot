[Slide 3] 시스템 아키텍처: 100% 오픈소스 에코시스템 결합 (01:25 ~ 02:25, 약 60초)
--------------------------------------------------------------------------------
[화면 설명]
- 4단계 End-to-End 파이프라인 구조
  1. 수집 & 파싱: Playwright + Tesseract + olefile + pypdf
  2. 저장 & 임베딩: ko-sroberta-multitask + ChromaDB
  3. RAG 코어: LangChain + 도메인 리랭커
  4. 서빙: FastAPI 비동기 백엔드 + HuggingFace 로컬 SLM + React 모바일 웹

[발표 대본]
"CampusRAG의 시스템 아키텍처입니다. 전 과정이 검증된 오픈소스 소프트웨어로 유기적으로 연결되어 있습니다.

1단계 데이터 엔진은 Playwright 크롤러와 함께 오픈소스 OCR인 Tesseract, 그리고 HWP 바이너리를 직접 파싱하는 olefile을 통해 비정형 첨부문서를 완전 텍스트화합니다.

2단계 벡터 스토어는 한국어 학사 문맥에 특화된 오픈 임베딩 모델 ko-sroberta-multitask와 오픈소스 벡터 DB인 ChromaDB를 로컬 파일 기반으로 구축했습니다.

3단계 도메인 RAG 코어에서는 단순 코사인 유사도의 한계를 극복하기 위해, 학사 특유의 연도와 학기를 보정하는 자체 리랭킹 알고리즘을 LangChain 오픈소스 프레임워크 기반으로 구현했습니다.

마지막으로 서빙 레이어는 0.1초 만에 헬스체크를 통과하는 비동기 FastAPI 백엔드와 경량 오픈소스 SLM인 Qwen과 Gemma를 로컬에서 직접 구동할 수 있는 하이브리드 서빙 구조를 갖추었습니다."

"저희 팀이 집중한 첫 번째 오픈소스 기술적 성과는 '외부 상용 변환기 없는 자체 문서 파싱 파이프라인'입니다.

한국 대학 공지의 필수 포맷인 HWP 5.0 문서를 상용 한글 프로그램 없이 파이썬 olefile 라이브러리로 zlib 압축 스트림을 해제하고 레코드 태그를 직접 파싱하여 본문을 추출했습니다. HWPX 역시 표준 XML 파서로 무손실 추출합니다.

PDF는 텍스트 레이어를 초고속으로 읽는 pypdf를 1차로 적용하고, 스캔된 이미지 PDF는 pypdfium2로 고해상도 렌더링 후 오픈소스 Tesseract OCR로 자동 폴백되는 이원화 파이프라인을 구축했습니다.

여기에 크롤러가 사설망 내부 IP로 접근하는 것을 원천 차단하는 SSRF 보안 방어와 20MB 용량 제한, SHA-256 해시 기반 캐싱을 적용해 오픈소스 소프트웨어로서의 프로덕션 레벨 안정성을 확보했습니다."

1. Q: "오픈소스 LLM(로컬 모델)만으로도 충분한 요약 품질이 나오는가?"
   A: "RAG의 품질은 '검색된 청크의 정확도'에 80% 이상 좌우됩니다. 도메인 리랭킹과 HWP 파싱으로 정확한 공지 본문이 주어지기 때문에 Qwen2.5-1.5B나 Gemma-2-2b 같은 경량 SLM으로도 충분히 사실에 기반한 2~3줄 요약이 가능합니다."

2. Q: "상용 프로그램 대신 olefile로 HWP를 직접 파싱한 기술적 이유는?"
   A: "Windows 전용 한컴 COM 객체나 유료 API를 쓰면 Linux Docker 컨테이너 배포가 불가능합니다. 크로스 플랫폼 독립성과 서버 배포의 자유도를 위해 순수 파이썬 오픈소스인 olefile로 바이너리를 직접 언팩했습니다."

3. Q: "타 대학 확장 가능성은?"
   A: "수집기, 비정형 문서 파서, 리랭커가 완벽히 모듈화되어 있습니다. 타 대학의 공지 게시판 URL 패턴만 설정 파일에 넣으면 즉시 작동 가능한 범용 오픈소스 프레임워크를 목표로 하고 있습니다."

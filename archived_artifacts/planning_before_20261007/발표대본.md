### [01:25 ~ 02:35] Part 2. PRD (제품 요구사항 정의서) 발표 (약 70초)

> **[화면 조작]** `저학년의 반란_CampusMate_PRD_v1.0_20260919.docx`의 [핵심 기능(MVP) 표] 및 [사용자 흐름(User Flow)] 표출  
> **[핵심 강조]** 대학생의 페인포인트 -> MVP 핵심 기능(F-01~F-06) -> 성공 기준 연결

"이어서 제품의 상세 스펙을 담은 **PRD(Product Requirements Document)**입니다.

저희 서비스의 주요 타깃은 여러 과목의 과제, 시험, 비교과 공지를 챙겨야 하는 대학생입니다.  
현재 학생들은 공지 확인 채널이 분산되어 입력을 빠뜨리거나 마감일을 놓치는 고질적인 페인포인트를 겪고 있습니다.

이를 해결하기 위해 정의한 **CampusMate의 6대 핵심 MVP 기능**입니다.
- 계정 접근을 위한 **F-01 회원가입/로그인**,
- 시험·과제 CRUD를 처리하는 **F-02 일정 관리**,
- 가장 핵심인 **F-03 AI 일정 추출**입니다. 학생이 '9월 25일까지 AI·SW 프로젝트 PRD 제출'이라고 자연어로 입력하거나 공지 링크를 넣으면, AI가 과목명, 일정명, 마감일시를 자동으로 파싱합니다.
- 추출된 정보를 검증하는 **F-04 확인 후 저장**,
- 이를 한눈에 시각화하는 **F-05 대시보드 및 통합 캘린더**,
- 그리고 마감 2일 전, 당일 푸시를 보내는 **F-06 마감 알림** 기능입니다.

사용자 흐름은 '로그인 → 자연어 입력 → AI 추출 → 사용자 확인 → 캘린더 표시 및 알림'의 초간결 단일 동선으로 설계했으며, 기술 스택은 React 모바일 반응형 UI와 FastAPI 백엔드, PostgreSQL 및 ChromaDB를 결합했습니다.

PRD의 최종 검증 기준은 **재학생 10명 대상 UT 수행, 치명적 결함 0건, 사용성 만족도 5점 만점에 4.0 이상** 달성입니다."

"다음은 실제 개발 실행 계획인 **WBS(Work Breakdown Structure)**입니다.

저희 WBS는 크게 **Inception(착수)**, **Sprint #1**, **Sprint #2**, 그리고 **Retrospective(회고/배포)**의 4단계 라이프사이클로 체계화되어 있습니다.

현재 진행 현황을 보고드리면,
- **1단계 Inception(착수)**은 현재 **70%의 높은 진척률**을 달성했습니다.  
  1.1 프로젝트 헌장 작성 및 1.1.1 헌장 수정 승인을 완료했고, 학내 공지 데이터 구조 분석과 Git 브랜치 전략, 개발 컨벤션 수립을 마쳐 킥오프 준비를 완벽히 끝마쳤습니다.
- **2단계 Sprint #1**은 현재 **19% 착수 상태**입니다.  
  공지사항 웹 크롤러 기초 모듈과 HWP/PDF/OCR 파일 파서 개발, 그리고 ChromaDB 임베딩 파이프라인 구축 및 SSRF 보안 예외 처리를 이번 주차 내에 집중적으로 완수할 예정입니다.
- 이어지는 **Sprint #2**에서는 LangChain 기반 RAG 체인과 FastAPI REST API, 그리고 React 모바일 웹 UI 연동을 완결하고,
- **4단계 Retrospective**에서 RAG 정확도 테스트, Docker 컨테이너 패키징 및 Cloudtype 클라우드 배포, 오픈소스 라이선스 검증을 거쳐 최종 릴리즈를 진행할 계획입니다."

### Q2. "WBS 상에서 현재 가장 큰 기술적 도전 과제나 병목(Bottle-neck)은?"
> **답변 (15초)**:  
> "Sprint #1의 HWP 파일 파싱과 Tesseract OCR의 처리 속도 및 정확도입니다. 이를 위해 상용 프로그램 없이 순수 오픈소스인 `olefile`로 바이너리를 직접 디코딩하고, SHA-256 해시 캐싱을 적용해 서버 부하를 최소화하는 방어 설계를 완료했습니다."

### Q3. "PRD에 정의된 사용자 만족도 4.0 이상과 UT 10명 평가는 어떻게 진행할 계획인가?"
